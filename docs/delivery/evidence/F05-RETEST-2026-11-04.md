## Defect and fix

`AndroidReminderPlatform.CleanNotifications` called `CancelAll()` for an empty valid-key set. Routine enabled/allowed reconciliation with no eligible dues therefore removed the explicit static test notification. This reproduces a disappearing test notification on refresh; other scheduled-delivery conditions are assessed separately.

`IReminderPlatform.CleanNotifications` now receives `keepTestNotification`. The coordinator sets it when reminders are enabled and notification access is allowed. Android preserves the `duewise-test` tag in that case, including an empty queue; obsolete due tags still disappear. Disabled or blocked access clears both test and due notifications. Empty alarm/job queues still cancel scheduling. No schema, dependency, money/date policy, due mutation or notification payload change was introduced.
