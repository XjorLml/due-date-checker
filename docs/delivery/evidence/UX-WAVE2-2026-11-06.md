## Defect found and fixed: migration errors could be lost

While testing RC01's rollback scenario, a conflicting index name made the last statement of migration 005 fail, yet `Initialize()` reported success and committed schema 5 without the index. Probes showed the cause. An `ALTER TABLE … ADD COLUMN` with a CHECK reports one result column (as a SELECT does), and Microsoft.Data.Sqlite's `ExecuteNonQuery` then runs the remaining statements while disposing its reader, where their errors are discarded. The runner now reads every result with `NextResult()`, which surfaces the error inside the migration transaction. The rollback test passes and is the regression test. Shipped migrations were not affected: 002's CHECK column is its only statement, and 003/004 contain no statement that reports result columns.
