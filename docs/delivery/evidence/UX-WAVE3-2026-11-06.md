# UX Wave 3 — Export and import dues (UX05), 2026-11-06

Scope: [UX improvements](../../../specs/ux-improvements/spec.md) UX05 (option A, JSON with a format version number), decided by the user on 2026-11-06 ([decision log](../../../specs/ux-improvements/spec.md#decision-log)) and started on the user's instruction "start wave 3". At the start of the wave the user also decided that "empty" means no dues on screen (hidden deleted dues do not block an import; a file due replaces a hidden one with the same ID). Behavior follows [EX01–EX08](../../../specs/f04-export-import/spec.md#acceptance-scenarios) and [ADR 010](../../adr/010-export-import-file.md). All observations are agent-observed on 2026-11-06. Emulator evidence only; the phone still holds a build signed by another computer.

New Core coverage: export then import into an empty database reproduces all fifteen columns of five varied rows. The rows include a tombstone, an occurrence with its source link, no amount versus zero, another currency and timezone, a +08:00 timestamp, and quotes, ñ and ₱ in text. The file has the documented field order. Thirteen kinds of non-export input are refused: not JSON, wrong root, other format, version 0 / string / fraction, missing or malformed `exportedAt`, `dues` not an array, an extra field, a repeated field, a comment. Invalid UTF-8 is refused, a newer version is reported before its contents are read, and empty or oversize files are refused. A byte order mark is accepted. Twenty-three spoiled dues are refused, each naming its position and field, and a repeated ID is refused. Upper-case IDs and padded titles are stored in the app's own form. Import is refused while a due shows; hidden deleted dues stay, and a matching one is replaced. A failure on the second row (a controlled trigger) rolls back the first. The store re-validates records passed to it directly.

New App coverage: the export file name follows the Manila date (17:00 UTC on 05 Nov → `2026-11-06`); export counts, nothing-to-export without a dialog, cancel and save failure. Import confirmation text and counts are covered, as are the full write with reminder refresh, refusal before the dialog while dues show, and hidden deleted dues not blocking. Cancel at the dialog and at the confirmation, plus seven refusal messages, write nothing; so does an oversize file, which also checks the size limit is passed to the dialog. Unreadable files and failed writes are reported. A due added between choosing and confirming blocks the import, and repeated taps while a dialog is open start nothing more.

The Core test class first took 8 s because every test created two databases; databases are now created only by tests that use them (2 s).

## Limits

- No phone check: other file apps (Google Drive, the Xiaomi file manager) were not tried; they may label `.json` files differently or handle "write" mode differently.
- No TalkBack (not on this emulator image); announcements were verified as text in tests only.
- The emulator restore used soft-deletes made with `sqlite3`, not the app's Delete button; the resulting rows are the same shape (`deleted_at` and `updated_at` set).
- If Android kills the app while a file dialog is open, that dialog's answer is lost and the user must start again; not exercised.
- Screenshots `w3-settings-card`, `w3-save-dialog`, `w3-import-confirm` and `w3-settings-dark-200` are in the session scratchpad, not committed.
