# Duewise design exploration: audit and decisions

Audit recorded on 2026-11-04 before implementing this separate exploration. Inspected [the existing prototype](../mobile-review/index.html#dashboard), its [screen logic](../mobile-review/app.js), [styles](../mobile-review/styles.css), [model](../mobile-review/model.js), [review](../mobile-review/REVIEW.md) and [browser checks](../mobile-review/tests/browser-check.cjs), alongside [DESIGN](../../docs/DESIGN.md#scope-and-authority), [PRD](../../docs/PRD.md), [SDD navigation](../../docs/SDD.md#6-ui-and-navigation), native Dashboard/Calendar XAML and their App tests. These are source-backed design observations, not results from a user study.

## Existing experience and proposed improvements

| Area | Observation | Revision to explore |
|---|---|---|
| Hierarchy | The compact-action revision saves space, but long introductory headings and supporting prose still compete with financial facts. | Put the next date, known upcoming amount and urgency first. Limit descriptive prose inside the app. |
| Dashboard | Global paid progress is correct but does not directly answer how much is due next. Search, summary and chips remain a long vertical sequence. | Short summaries with explicit date scopes; immediate next-due row; compact search/filter affordances. |
| Navigation | The existing review studio has nine page choices. Those are review tools, not a recommended in-app navigation model. | Give all four concepts the same Dashboard / Calendar / Dues / Settings navigation; preserve the existing three-tab production contract separately. |
| Buttons | The existing 44-pixel icon controls and persistent Save are useful improvements. Further shrinking touch areas would undermine usability. | Keep named icons and compact Save, replace repeated actions with one contextual entry, and retain visible navigation labels. |
| Due rows | A separate title, category, amount, date and badge on every card makes a short list tall. | Compare open ledger rows, layered dark cards, softer grouped cards and a compact dated timeline. Allow long amounts/titles to wrap. |
| Categories | Literal category labels work, but all generic icons look similar at a glance. | Shared recognizable category glyphs with tested foregrounds; never use color as the only category/status cue. |
| Dates | Month counts and agenda are useful; weekly navigation is absent. | Add a month/week switch over the same exact calendar dates and keep selected-day details one tap away. |
| Recurrence | Production recurrence is deferred; the existing HTML does not configure it. | A clearly marked prototype-only repeat selector and next-occurrence preview. Do not generate or charge a series. |
| Reminders | The current prototype explains simulation accurately, but long diagnostic copy distracts from the schedule. | A concise status, global schedule and quiet-hour fields, with secondary explanations inside disclosure. Explicit opt-in stays separate from Save. |
| Accessibility | Reference 44-pixel actions, visible focus, labels and semantic statuses are present; browser geometry is not native accessibility acceptance. | Check focus return, dialog behavior, labels, contrast, responsive widths and text reflow. Keep native TalkBack/keyboard/system-text acceptance open. |
| Feedback | Toasts confirm writes, but changing a page or theme can disturb scroll/focus if everything is rebuilt. | Preserve drafts and view state across concept switches; keep previews generated by shared rendering/state logic. |
| Empty/error | The previous prototype has useful state previews. | Keep distinct empty/no-match/loading/read-error/stale/unavailable states in the new sandbox. |

## Four directions, without a default winner

| Direction | Visual/structural hypothesis | Tradeoff to assess |
|---|---|---|
| A — Minimal Fintech | Warm neutral canvas, dark ink, lime accent, large financial typography and open rows. | Efficient scanning; less visual separation between entries. |
| B — Premium Dark | Charcoal layers, violet highlights, a restrained hero glow and outlined dark cards. | Strong focus and depth; dark contrast and fine borders require careful checks. |
| C — Friendly and Intuitive | Soft peach/teal accents, rounder groups, familiar category icons and short guidance. | Approachable; avoid decorative colors overwhelming urgency. |
| D — Data-Driven Dashboard | Blue/teal analytical panels, dated timeline, count breakdown and weekly amounts. | More context; avoid showing too many metrics above the next action. |

Each option must use the same fixture, calculations and interactions. Previewing A first is alphabetical browsing, not preference selection. The saved choice starts empty and can be changed or cleared. No implementation winner is chosen by the agent.

## Reference research

The following official sources were consulted on 2026-11-04. The proposed visual directions are designer interpretations, not claims that these products use our exact layouts:

- Revolut centralizes several insights and provides a time-period selector. The transferable idea is explicit information scope, rather than copying financial-account widgets into a dues tracker. [Revolut analytics dashboard](https://help.revolut.com/en-US/help/accounts/budget-and-analytics/what-is-the-analytics-dashboard/).
- Wise presents send, spend and manage as clear tasks. The exploration borrows concise task hierarchy, not currency/account capabilities or the company’s interface. [Wise account](https://wise.com/gb/account/).
- Monzo explains bills as a recognizable group and provides a focused scheduled-payments entry. This supports clearer bill grouping; Duewise does not gain bank Pots or payment execution. [Monzo bills from Pots](https://monzo.com/help/monzo-plus/web-bill-pots).
- YNAB offers category/group breakdowns with percentages. The new sample chart uses counts of dues, explicitly not spending or budget history. [YNAB spending breakdown](https://www.ynab.com/whats-new/spending-breakdown-reflecting-on-web).
- Copilot separates upcoming recurring items from other dashboard sections and describes important exclusions in its spending chart. The transferable idea is separating forecast obligations from historical spend and explaining the calculation. [Copilot dashboard overview](https://help.copilot.money/en/articles/6045480-dashboard-tab-overview).

## Scope conflicts resolved for this artifact

The user's brief authorizes broader **prototype** exploration, while the PRD still governs production. New palette alternatives, four destinations including Settings, Dashboard-first entry, weekly Calendar, amount aggregates, quick status changes and recurrence controls are labeled exploration proposals. They do not alter the original prototype, native routes, database, release state or canonical tokens.

Current semantics remain available: PHP, Manila calendar dates, fixed categories, no amount versus zero, chronological saved dues, paid draft on editor Save, explicit Cancel and confirmed deletion without Undo. A quick “Mark paid” action in the exploration asks for confirmation; it is a proposed shortcut, not the existing production editor flow. Use **Paid**, not an invented payment-history series or task-completion lifecycle.

Headline amount means known unpaid sample amounts dated from sample Today through the end of that month, including today and excluding overdue. Amount-less entries are counted and explicitly excluded from sums; a present zero is included as zero. The separate overdue count/amount prevents hidden obligations. Charts aggregate due dates or counts, never payment dates. All calculations use integer centavos. Recurrence is a saved sample preference plus a date preview; it never generates future rows. A month-end repeat clamps the next preview to the destination month’s last day. A later production slice must define occurrence identity, series mutation and scheduler integration independently.

Settings and reminder edits remain drafts until Save or explicit Save & enable. Notification interactions are simulation only. No account, bank balance, money transfer, backend, real permissions or scheduling is implied. The side-by-side comparison and personal preference export persist only review choices/notes; financial fixtures remain in memory.
