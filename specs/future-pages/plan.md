- Add DashboardPreviewPage and CalendarPreviewPage with shared read-only PreviewItemView cards, semantic theme resources and the existing responsive PageLayout helper.

- Dashboard filters and calendar selection update local preview state. A native drawable ring reflects the same completed/total counts. Calendar uses a seven-column grid with 48 dp minimum date targets and horizontal overflow on compact widths.
- Verify MP01–MP05 with pure state tests, existing regression suites, Android build and available phone checks. Record unperformed accessibility/device acceptance explicitly. No release or real-data integration follows from a mock pass.

## Navigation direction

Proposed destinations, **not registered routes**:

```text
Onboarding (first run) -> Home
Home / Calendar -> Item detail -> Existing editor
Home -> Settings -> Notification settings
Settings -> Account (only after the cloud slice ships)
```

Budgets/savings placement and future tab composition remain design decisions after those pages have approved scope. Current saved-data navigation is Dues → Details → editor, with direct Add → editor unchanged. The authorized bottom bar exposes the two labeled previews as peer destinations; Details/editor hide the bar. Future Home/Calendar → Details integration is still proposed, not a sample-card action.

## Entry checklist for each implementation slice

1. Confirm the page's product rules and resolve its [open decisions](spec.md#product-decisions-to-resolve-per-slice). Review/update PRD requirement identities and acceptance outcomes without rewriting historical v1 evidence.
2. Create a dedicated feature spec/plan/tasks with positive, negative, offline, restart, error/retry and accessibility scenarios. Link the exact DESIGN sections and SDD contracts.
3. Define any migration, repository, clock/preference, permission, scheduler or network contracts; record significant supported architecture decisions in an ADR when needed.
4. Implement behavior before exposing its navigation/control. Reuse semantic styles, local fonts, responsive margins and state patterns from design adoption.
5. Run meaningful domain/App checks, Android build and targeted native acceptance; record source/artifact/environment and observer. A future page is not complete because its route or XAML exists.

Current [PRD exclusions](../../docs/PRD.md#exclusions-and-deferred-capabilities) continue to apply.
